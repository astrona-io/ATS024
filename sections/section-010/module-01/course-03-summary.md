# Summary

Rollouts replace changed templates under surge and availability controls. Readiness, percentage rounding and usable replacement capacity influence progress.

A deadline condition does not automatically perform recovery. Earlier template history does not preserve every external dependency, so rollback needs current compatibility and meaningful application verification.

You can now calculate the controller budget and explain a stalled update using Pod evidence. The chosen correction must address the cause; a larger allowance does not repair an invalid image or a failed application check.
